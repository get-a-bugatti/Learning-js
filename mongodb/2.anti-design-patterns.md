
## Anti-Pattern: Unbounded Array

### What is it?

An **Unbounded Array** is an array that **continues to grow indefinitely** as new elements are added.

Example:
```
{
    _id: 1,
    title: "MongoDB Basics",

    reviews: [
        {...},
        {...},
        {...},
        ...
        // millions of reviews
    ]
}
```
---

### Why is it bad?

* Increases document size.
* Slower reads and writes.
* Higher memory and storage usage.
* Can exceed MongoDB's **16 MB document limit**.
* MongoDB reads the **entire document**, even if only one field is needed.

---

### Common Examples

* Reviews
* Comments
* Likes
* Followers
* Chat messages
* Activity logs

---

### When are arrays okay?

Arrays are fine if they have a **small or bounded size**, such as:

* Authors
* Tags
* Phone numbers
* Categories

---

### Solutions

* **Reference Pattern** → Store growing data in a separate collection.
 Move array items into another collection.
    ```
    Book
        ↓
    Review Collection
    ```
    Each review references the book using `book_id`.

* **Subset Pattern** → Embed only recent or frequently accessed items.
    Example
    ```
    {
        title: "MongoDB",

        recentReviews: [
            {...},
            {...},
            {...},
            {...},
            {...}
        ]
    }
    ```
    Older reviews remain in a separate reviews collection.

* **Bucket Pattern** → Split large arrays across multiple documents.


---

### Takeaway

Avoid embedding data that can **grow without limit**. Use references or other schema patterns to keep documents small and queries efficient.

## Anti-Pattern: Bloated Documents

### What is it?

A **Bloated Document** stores **too much data in a single document**, including fields that are rarely used or unnecessary for most queries.

---

### Why is it bad?

* Larger documents take longer to read and write.
* Wastes memory and storage.
* Transfers unnecessary data over the network.
* Can negatively impact query performance.

---

### Example

❌ Bad

```js
{
    _id: 1,
    title: "MongoDB Basics",
    content: "...",
    reviews: [...],
    authorDetails: {...},
    publisherDetails: {...},
    salesHistory: [...],
    analytics: {...}
}
```

Most queries may only need the `title`, but MongoDB still reads the large document.

---

### Solutions

* **Subset Pattern** → Keep frequently accessed fields in the main document; move infrequently used data elsewhere.
* **Reference Pattern** → Move large or rarely used data into separate collections.
* Use **projection** (`$project` or field selection) to return only required fields.

---

### Takeaway

Keep documents **lean** by storing only frequently accessed data together. Move rarely used or large data into separate documents or collections to improve performance.
